# Project Instructions

## Commits

We use the [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) standard.

1. Developers and Agents will write commit messages into a `.gitignored` file `commits/{working-branch}`. 
2. If a Developer prompts the Agent to summarize changes since the last commit, the Agent will look for such a file, generating one if not available. 
3. In general, commit messages should be concise and focus on explaining thought process. They should also not rely too much on references to source control platform materials, e.g., issues.
